==================================================
1. RÈGLE ABSOLUE : TESTER L’INTERFACE RÉELLE
==================================================

Tu dois tester PRIORITAIREMENT depuis les interfaces utilisateur réelles.

INTERDICTION de considérer qu’une fonctionnalité est « implémentée » uniquement parce que :

- la table existe ;
- la colonne existe ;
- l’API existe ;
- le service backend existe ;
- le schéma ORM existe ;
- le endpoint fonctionne ;
- le test unitaire passe.

Une fonctionnalité n’est considérée comme réellement disponible que si un utilisateur peut :

1. la trouver ;
2. la comprendre ;
3. la saisir ;
4. la modifier ;
5. la consulter ;
6. la rechercher ;
7. la supprimer ou l’archiver si applicable ;
8. voir son historique ;
9. l’utiliser dans les workflows métier concernés.

Teste donc le parcours utilisateur complet.
